dartive library

dartive (dart + rive): a from-scratch Dart scene-graph/game-action/state library, grown out of products/squishy-mascot-twin's hand-rolled puppet rendering. Pre-1.0 "seed" stage — see this package's own .context/decisions/0001-dartive-seed-genesis.md for what that means.

Classes

IsoCamera Projection
A fixed-elevation isometric camera, rotatable around the vertical axis.
MazeGenerator Grid
A static, generated rectangular maze — one particular kind of Tilemap: a walled one. Extracted into dartive after the same recursive-backtracker algorithm had been hand-copied and re-adapted across three products in a row — my-rownie-run-item's original, ported into my-atlas-run-item's MazeBoard, then into my-astronaut-run-item's own MazeGenerator (square size only) — before raon-runner-platform-mockup/apps/maze-run-demo's village board needed a rectangular (20×10) board and made the duplication worth stopping. Extends Tilemap (not a separate concept from it) since the user asked for the "open board" case — a village with no walls — not to be confused with "a maze," the same distinction my-atlas-run-item's RunBoard.isMaze flag already drew between MazeBoard and AtlasRunBoard. See .context/decisions/0012-maze-and-joystick-extraction.md and 0014-tilemap-extraction.md. Standard "recursive backtracker" over the chambers at even coordinates; every odd-coordinate cell starts as a wall, and a wall slot between two chambers is removed exactly when the carve reaches between them. A fixed seed, so this is one learnable maze, identical every load — not regenerated per session. Pure Dart, no Flutter dependency, so it's directly unit-testable (agent-harness-patterns.md's "keep state and rendering separate," applied one layer further down than usual).
RearmableTimer Motion and input
A Timer that can be re-armed (cancel the pending firing and schedule a new one) without the caller hand-tracking a nullable Timer? field and repeating the _timer?.cancel(); _timer = Timer(...) dance. Pure dart:async — no Riverpod, no scheduling policy of its own; the caller still decides durations and callbacks, arm/cancel are just the lifecycle plumbing.
Tilemap Grid
A rectangular (width×height) grid of cells a character can stand on and move across, with a per-cell walkable/blocked check — the convergent shape every *Board class in this factory already reinvents on its own: RunBoard/MazeBoard/AtlasRunBoard (my-atlas-run-item, isMaze flag distinguishing a walled board from an open one), PartnerBoard (my-astronaut-run-item, always open), ExplorerBoard (voxel-explorer-spike, open + zone-tinted). None of those were built from this — this is the first time the shape itself is shared.
TouchJoystickCanvas Motion and input
Wraps child (the map canvas) with a touch-to-summon virtual joystick: touching the canvas and dragging past a small reveal threshold shows a base+knob anchored at the touch-down point, reporting one of the 4 JoystickDirections. A touch that never exceeds the reveal threshold (an ordinary tap) never shows anything.
Vec3 Linear algebra
An immutable vector v = (x, y, z) ∈ ℝ³ in world space, with the factory's right-handed axes: +x right, +y up, +z forward.
VoxelPuppet Voxels
A sparse grid of colored unit cubes — a puppet built out of voxels instead of bones/parts. State only: knows nothing about how it gets drawn (see VoxelPuppetPainter in voxel_puppet_painter.dart) — same state/render split as every other product in this factory. Coordinates are grid-cell indices (0..size-1 per axis), not world units.
VoxelPuppetPainter Voxels
Renders a VoxelPuppet as flat-shaded, depth-sorted unit cubes under a given camera — backface-culled, and faces fully hidden by a neighboring voxel are skipped before that, so this stays cheap even at a puppet's full grid size. camera is a constructor parameter, not a fixed field, so the same puppet can be painted from several angles at once (see products/voxel-asset-bakery's multi-view panel for a consumer that does exactly that).

JoystickDirection Motion and input
Extracted into dartive from products/my-astronaut-run-item/lib/screens/touch_joystick.dart — that product's own .context/decisions/0021-restore-joystick-axis-labels.md/ 0020/0018/0010 carry the full history of why it works this way (reasoning that stays valid here unchanged). Extensions

VoxelPuppetIo on VoxelPuppet Voxels
Serialization for VoxelPuppet — plain JSON (grid size + a flat list of {x,y,z,color} cells), not a Dart-source literal or a binary format: any consuming product can parse this with nothing but dart:convert, no extra dependency beyond dartive itself.

Functions

dipAndRecoverPulse(Duration elapsed, {required Duration rising, required Duration falling}) → double Motion and input
1.0 outside the pulse window, dipping to 0.0 and back as elapsed runs from zero to rising + falling — a brief "close, then reopen" shape. Ordering matches Rive's own "Interpolation on States": a value eased into a state, then eased back out, driven by however the caller decides when the pulse starts (a timer, a trigger — dartive stays pure math, no scheduling; see this package's own CLAUDE.md).
gridBfsPath({required (int, int) start, required (int, int) goal, required bool isBlocked(int x, int z), required int width, required int height}) → List<(int, int)>? Grid
Breadth-first shortest path over a 4-connected integer grid — the standard unweighted-graph shortest-path algorithm, scoped specifically to "a small rectangular grid, 4-directional movement, every edge the same length," which is what a mini-game board typically is. Not a general graph library.
isoTileCenter(IsoCamera camera, num x, num z, {double scale = 1.0, Offset origin = Offset.zero}) → Offset Projection
The screen point for the center of unit cell (x, z) — the usual anchor for a marker (avatar, pickup, prop) sitting on that cell, rather than one of its corners.
isoTileCorners(IsoCamera camera, int x, int z, {double scale = 1.0, Offset origin = Offset.zero}) → List<Offset> Projection
The 4 corners of one unit cell (x, z) of a ground-plane grid (y fixed at 0), projected through camera — in order (x,z) → (x+1,z) → (x+1,z+1) → (x,z+1), ready to build a quad for an isometric floor/wall tile. origin shifts the whole projection (e.g. to center a board on a canvas); scale matches IsoCamera.projectOrthographic's own scale.
isoTilePath(IsoCamera camera, int x, int z, {double scale = 1.0, Offset origin = Offset.zero}) → Path Projection
The same 4 corners as a closed Path, ready for canvas.drawPath.
perspectiveTurnX(double angleRadians, {double depth = 0.001}) → Matrix4 Projection
The up/down sibling of perspectiveTurnY: rotateX turns around the horizontal axis — like a trunk lid hinged front-to-back — so the visible motion is a tilt/nod (up/down), not left/right.
perspectiveTurnY(double angleRadians, {double depth = 0.001}) → Matrix4 Projection
A perspective "card flip" matrix that fakes a rotateY head/body turn for a flat 2D puppet with no real mesh — setEntry(3, 2, depth) adds the projective divide a plain rotateY lacks, so the far side visually compresses instead of just shearing. Apply around the part's own local origin (translate first, then canvas.transform(matrix.storage)).
voxelPuppetFromJson(String source) → VoxelPuppet Voxels
Rebuilds a VoxelPuppet from VoxelPuppetIo.toJson's output (or an equivalent hand-written JSON asset).
