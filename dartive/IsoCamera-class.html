IsoCamera

IsoCamera class Projection

A fixed-elevation isometric camera, rotatable around the vertical axis.

Contract (spec doc/spec/projection.md, PRJ-1..PRJ-5). With azimuth α and elevation ε = atan(1/√2):

c = (cos ε cos α, sin ε, cos ε sin α)   camera position direction
forward = −c          right = (sin α, 0, −cos α)
up = right × forward = (−sin ε cos α, cos ε, −sin ε sin α)

(right, up, forward) is an orthonormal basis (PRJ-1). projectOrthographic is the rank-2 linear map Π(p) = scale·(right·p, −up·p) with ker Π = span(forward) (PRJ-2). On the ground plane y = 0 it is the 2×2 matrix G = S·R, a rotation R followed by a vertical squash S = diag(1, sin ε), so det G = sin ε = 1/√3 for every azimuth and G is always invertible (PRJ-3).

Default elevation=atan(1/sqrt(2)) (~35.264°) — the angle at which a cube's three visible faces are foreshortened equally, viewed from the (1,1,1) direction. Orthographic projection only (no perspective divide), so parallel lines stay parallel — this is the technique classic isometric art uses. azimuthDegrees (default 45°, the classic corner view) rotates the camera around the model without changing elevation, letting a caller render the same model from several angles at once (see products/voxel-asset-bakery/lib/voxel_look/camera_presets.dart for a worked example).

Precisely which angle is "45°" — recorded here since it's easy to misplace which of the two angles is which. This factory's own world axes: +x = right, +y = up, +z = forward (Vec3's own doc comment). The camera's direction is built from altitude-azimuth spherical coordinates (the astronomy/game convention — elevation measured up from the horizontal x-z plane — not the physics- textbook convention of a polar angle measured down from the vertical axis):

x = cos(elevation) * cos(azimuth)
y = sin(elevation)
z = cos(elevation) * sin(azimuth)

azimuthDegrees (45° by default) is azimuth — the rotation angle, measured entirely within the horizontal x-z plane, between the +x axis and the camera's direction, sweeping toward +z. Equivalently: looking straight down the +y axis at the ground plane and ignoring height entirely, it's the angle between +x and the object-to-camera line in that bird's-eye view. elevation (fixed at ~35.264°, not adjustable via this constructor) is a different angle — how far that direction tilts up out of the horizontal plane toward +y — and is not "the 45°" this class's name or call sites refer to.

Azimuth = 45° specifically is why IsoCamera-based movement never reads as screen-horizontal/vertical no matter which world axis you move along: cos(45°) == sin(45°) (both 1/√2), so the camera direction's x and z components are exactly equal — neither world axis is favored, so both project to an equally diagonal screen direction. (See voxel-explorer-spike's own ExplorerBoard.move() doc comment for the empirically-verified screen-direction table this produces, and that product's README §5 for the fuller worked explanation aimed at a non-graphics background.)

Not the same class as squishy-mascot-twin's own Camera3D (lib/mascot/render/space3d.dart) — that one is a general position/ target perspective-or-orthographic camera, deliberately hand-rolled there for pedagogical reasons (see that file's own doc comment) and left untouched by this extraction. IsoCamera is the narrower, azimuth/elevation-parameterized shape this package's own voxel-puppet rendering actually needs.
