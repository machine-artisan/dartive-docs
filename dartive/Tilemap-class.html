Tilemap

Tilemap class Grid

A rectangular (width×height) grid of cells a character can stand on and move across, with a per-cell walkable/blocked check — the convergent shape every *Board class in this factory already reinvents on its own: RunBoard/MazeBoard/AtlasRunBoard (my-atlas-run-item, isMaze flag distinguishing a walled board from an open one), PartnerBoard (my-astronaut-run-item, always open), ExplorerBoard (voxel-explorer-spike, open + zone-tinted). None of those were built from this — this is the first time the shape itself is shared.

Named Tilemap, not Board, to follow established game-dev vocabulary rather than invent dartive's own — this package's actual goal (helping Dart/Flutter developers connect with the wider game- dev world, not build something novel). Unity's Tilemap, Godot's TileMap, and Phaser's Tilemap all converge on this exact word for "a grid of cells, some of which block movement." (Unity separately has a Grid component for pure cell-coordinate layout with no walkability data at all — that role is already covered here by IsoCamera/isoTileCorners/isoTileCenter, not this class.) "Board" reads as a board-game term (chess/checkers) and was the first-draft name before this naming pass. See .context/decisions/0014-tilemap-extraction.md.

Open vs walled is just whether isWall is given a function. A village-style open tilemap is Tilemap(width: w, height: h) — no walls anywhere, the same "every cell is open" shape PartnerBoard/ ExplorerBoard hand-roll today. MazeGenerator is one walled tilemap — it extends Tilemap and overrides isWall from its own carved wallCells, rather than being a wholly separate concept from "a tilemap."

Math (GRD-1): the cell set Ω = [0, width) × [0, height) ⊂ ℤ² and a predicate wall: Ω → {true, false}. Walkable cells W = {c ∈ Ω : ¬wall(c)} with 4-neighbor edges form the graph gridBfsPath searches.
