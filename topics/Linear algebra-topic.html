Linear algebra (LA)

Notation used across every dartive spec page, plus Vec3.

Notation

ℝ³ world space, right-handed:  +x right · +y up · +z forward
ℤ² grid cells (x, z) — a cell index, not a world point
bold a, b       vectors          a·b   dot product      a × b  cross product
‖v‖             Euclidean norm   e_x, e_z  unit axis vectors
[[a, b],[c, d]] a 2×2 matrix, row-major; it maps (u, v) ↦ (a·u + b·v, c·u + d·v)
α azimuth, ε elevation = atan(1/√2) ≈ 35.264°, sin ε = 1/√3, cos ε = √(2/3)
screen space:   +x right, +y DOWN (Flutter's convention), units = pixels

Status: ✅ proved by a test · 📄 documented, not yet tested · 📝 proposed, not built

Definitions and invariants

ID Statement Status Test
LA-1 add/subtract/scale are componentwise; a.add(b).subtract(b) == a ✅ spec_linear_algebra_test
LA-2 dot is symmetric and bilinear; a·b = 0 ⇔ orthogonal ✅ same
LA-3 cross is anticommutative, orthogonal to both operands, right-handed (e_x × e_y = e_z) ✅ same
LA-4 normalize() has length 1; the zero vector is returned unchanged (never NaN) ✅ same
LA-5 Lagrange identity ‖a × b‖² = ‖a‖²‖b‖² − (a·b)² ✅ same

== is exact. Every spec test compares computed values with closeTo.

Not in dartive (deliberately)

There is no general matrix type yet. 4×4 work uses Flutter's Matrix4 (see PRJ-6), and the 2×2 ground matrix G (PRJ-3) is only derived in tests. A Mat2 gets extracted once a product needs G⁻¹ at runtime (PRJ-P1), per dartive's rule 1: extract, don't invent.
